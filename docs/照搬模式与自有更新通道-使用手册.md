## 一、这是什么

[workbuddy-switch](https://github.com/changexbc/workbuddy-switch)（作者 changexbc/zhangjia）是 WorkBuddy/CodeBuddy 的多账号切换桌面 App。我们在它的基础上维护一个 **own 版**，加了三块自有能力：

1. **照搬模式**（核心）：切号时把目标账号**完全变成当前账号的样子**——会话、置顶、侧栏排序、定时任务，一次切换全部照搬。
2. **自有更新通道**：应用内「检查更新」拉的是我们自己的自动构建（作者最新版 + 自有功能），不是作者的官方包。
3. **双机分线构建**：Intel 台式机和 Mac mini（Apple 芯片）各有一条独立构建线，互不干扰。

## 三、切号的三种会话操作

| 功能 | 做什么 | 目标账号原有内容 |
|---|---|---|
| **复制会话** | 把当前账号**勾选的**会话复制给目标账号（生成新 id） | 不受影响，重复复制自动跳过 |
| **关联会话同步** | 把当前账号的新增内容增量合并进目标账号的**已关联会话** | 保留原会话 id 和标题 |
| **照搬模式**（自有） | 见下节 | **先清空**，再照搬 |

## 四、照搬模式详解

切号弹窗底部勾选「**照搬模式：清空目标账号旧会话与定时任务，复制当前账号全部会话**」。勾上后自动发生四件事：

1. **自动全选**当前账号的全部会话（可再手动调整勾选）；
2. **清空目标账号的旧会话**——两种模式二选一：
   - **归档**（默认）：本地软删 + 云端归档，**随时可恢复**；
   - **删除**：云端彻底删除（所有设备同步消失）+ 本地软删 + 清同步映射，**不可逆**；
3. **定时任务单向覆盖**：目标账号的激活任务集 ← 当前账号的激活任务集（复制为新 id、归属改为目标账号；目标旧任务按所选模式软删/硬删）；
4. **侧栏快照迁移**：置顶（isPinned）与侧栏排序随复制映射迁移，未复制的会话对应条目自动丢弃。

执行顺序：清空旧会话 → 定时任务覆盖 → 复制新会话 → 侧栏快照迁移 → 写认证 → 启动。

### 安全机制（每次照搬都自动执行）

- 动手前**整个 workbuddy.db 备份**到 `~/.wb-switch/backups/overwrite-<时间戳>/`；
- 映射库（edge-sync）一并备份；
- WorkBuddy 运行中会拒绝执行（切换流程会先关 WorkBuddy，正常操作不受影响）；
- token 失效自动刷新重试一次。

## 五、数据都存在哪里

| 数据 | 位置 |
|---|---|
| 会话 + 定时任务（所有账号共用一个库） | `~/.workbuddy/workbuddy.db`（sessions 表按 user_id 区分；automations 表按 owner_user_id 区分） |
| **侧栏快照（置顶 + 排序，按账号一份）** | `~/.workbuddy/<账号uid>/sidebar-list-snapshot.json` |
| 启动路由（按账号） | `~/.workbuddy/<账号uid>/startup-route.json` |
| 登录态（当前账号） | `~/.workbuddy/workbuddy-desktop.info` |
| 账号池（token 等） | `~/.wb-switch/accounts.json` |
| 会话复制/关联映射 | `~/.wb-switch/session_links.json` + edge-sync-mapping-v4.db |
| 覆盖前自动备份 | `~/.wb-switch/backups/overwrite-<时间戳>/` |
| 定时任务同步脚本备份 | `~/.workbuddy/automation-backups/` |
| App 安装包备份 | `~/.wb-switch/workbuddy-switch.app.bak-<时间戳>/` |

## 六、恢复手册

| 场景 | 恢复办法 |
|---|---|
| 照搬错了，想要回目标账号的旧会话 | 打开 WorkBuddy → 会话列表「归档」区恢复（归档模式下全部可恢复） |
| 定时任务想找回被覆盖的旧任务 | 用 `~/.workbuddy/automation-backups/` 里最近的整库备份，或从 `~/.wb-switch/backups/overwrite-*/` 恢复 workbuddy.db（⚠️ 需退出 WorkBuddy 再恢复） |
| App 本身要回滚 | `cp -R ~/.wb-switch/workbuddy-switch.app.bak-<时间戳>/workbuddy-switch.app /Applications/`（先退出 workbuddy-switch） |
| 整库恢复 | 关 WorkBuddy → 用备份目录里的 workbuddy.db（含 -wal/-shm）覆盖 `~/.workbuddy/workbuddy.db` → 重开 |

## 七、更新体系

- **平时**：应用内点「检查更新」即可——更新源已指向我们 fork 的 Release（按各自架构取 latest-macos-<arch>.json），拉到的永远是「作者最新 + 自有功能」。
- **自动跟进**：GitHub Actions 的 auto-follow 每周一上午 10 点（北京时间）自动合并上游新版本进两条机器线，打 `v<版本>-own` 标签触发双架构构建并发布 Release；合并冲突会自动开 issue 通知手动处理。
- **手动发一版**（改了自有功能后）：
  ```bash
  cd 49_外部项目/own/workbuddy-switch
  git push fork macos11-x86_64 macos15-aarch64
  git tag v0.1.62-ownN && git push fork v0.1.62-ownN
  # ⚠️ tag push 后 build-macos15-aarch64 可能因 workflow 注册延迟不触发，
  #    兜底：gh workflow run build-macos15-aarch64 -R oliver7l/workbuddy-switch --ref <tag>
  ```
- **⛔ 不要**点应用内更新去装**作者官方包**（官方包没有自有功能，且公钥不同）。own 版的更新源已指向自己的 Release，点更新是安全的。

## 八、已知边界与 FAQ

- **照搬后目标账号激活定时任务是 0 条**：因为 Aaron 名下唯一一条任务本身是已删除/暂停状态，「完全一样」的语义就是 0 条。想反向（把 19942328729 的 20 条任务搬给 Aaron）需另做。
- **置顶为什么能/不能照搬**：置顶不在会话表里，在按账号的侧栏快照 JSON 里。照搬模式会迁移它；单独用「复制会话」（不勾照搬）不会迁移置顶。
- **19942328729 名下曾有 20 条定时任务**：2026-10-18 应用户确认已照搬清掉，可从 automation-backups 恢复。
- **本地跑 CI 相关命令**：`git push` 必须用 `fork` 远端（`origin` 是作者仓，无权限）；本地 clippy 检查 src-tauri 前需先 `touch src-tauri/binaries/agent-studio-runtime-$(rustc -vV | sed -n 's/^host: //p')`。
- **历史补丁与旧构建脚本**：收拢在仓库 `local/` 目录（原 21_WorkBuddy多账号/patches/ 与 scripts/ 里仍有原件，可清理）。
- **21_WorkBuddy多账号/scripts/ 里的 wb_*.py 脚本**：读写 `~/.wb-switch/` 的周边自研工具（切号、积分、同步等），与源码仓路径无关，迁移不受影响。
